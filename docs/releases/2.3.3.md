# Release checklist: 2.3.3

Filled 2026-11-28 for `v2.3.3`, from `docs/release-checklist.md`; cut on a green `check` (the nightly
and the newest-OpenCode run started on it, not waited on).

2.3.3 makes `wb chat on` stick. With its port held by something else, `wb chat on` put the web
app's switch back to off, so once the port came free it still needed a second `wb chat on`; and its
message blamed "another account's chat (or another program ...)" when the holder was the user's
own. Now, when the port is the user's own, the switch stays on (`web chat on, not up yet: …`) and
the web app comes up by itself once the port is free; no link shows until it answers. The message
names the holder when it is the user's own process: its pid and command.
