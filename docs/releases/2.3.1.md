# Release checklist: 2.3.1

Filled 2026-11-28 for `v2.3.1`, from `docs/release-checklist.md`; cut on a green `check`, the
nightly and the newest-OpenCode run recorded as they stand (the owner, 2026-11-27: cut it, and a
fix ships as a minor bump).

2.3.1 is one change: **Posting to GitHub**. The send dialog held work for hours while the owner was
away ("i walk away from the computer, so i cannot approve your requests to post ... work
stalls"). A Settings row now picks when anything is posted to GitHub for the user, an issue, a
comment or a pull request:

- **Automatic**: sent at once, no dialog.
- **Once a day** (the default): nothing waits on the user mid-work. A post goes into an outbox
  (`wb upstream post issue|comment`; `wb patch send` queues itself), and at the user's first typed
  turn of each day the host asks once, Send all or Not today. Settings lists the outbox with Send
  all and Drop all; `wb upstream send` in the user's own terminal sends it.
- **Never**: fixes stay local patches and posts stay drafts.

Both hosts, Claude Code's mod and OpenCode's plugin, follow the same mode, and only the user sets
it: a model's `wb upstream mode` is refused, and an edit or shell write of `upstream.json` or of
the daily yes is denied. Also since 2.3: `opencode.yml` runs the suite in three shards (#1648), and
the macOS nightly's tests hold (#1646, #1648).
